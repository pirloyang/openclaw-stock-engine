# 持仓变更登记规则 v1.0

**生效日期：** 2026-06-06
**适用范围：** 所有持仓变更（建仓/加仓/减仓/清仓/调整止损止盈）
**配套文件：** `TOOLS.md` 持仓节、`stock-signals/focus_watchlist.json`、`data/settlement.json`

> **核心原则：** 任何持仓变更必须**先核对券商截图 → 再写入 TOOLS.md → 同步 focus_watchlist → 必要时刷新 settlement.json**。任一步遗漏导致数据不一致，AI 后续报告会出错。

---

## 一、变更来源与触发方式

### S1 · 唯一信任源：辉哥的告知
- 持仓变更**只能由辉哥主动告知**触发：发送券商截图 / 文字说明 / 简单确认。
- **禁止** AI 根据脚本信号、行情数据"推断"持仓发生变更。
- **禁止** AI 在未确认的情况下自动修改 TOOLS.md 持仓节。

### S2 · 告知形式与处理
| 辉哥告知形式 | AI 处理流程 |
|---|---|
| 发券商截图 | OCR → 提取标的/数量/成本 → 与 TOOLS.md 对比 → 确认差异 → 写入 |
| 文字说明（如"买了 600345 200股 56.83"）| 提取字段 → 当日时间戳 → 写入 |
| 简单确认（如"清仓了 XX"）| 标的+清仓价/数量需追问 → 不要自己估算 |

## 二、字段标准（强制）

### F1 · 建仓登记字段
TOOLS.md 持仓节每条记录**必须包含**：

```
- <名称> <代码>（<数量>股，成本<成本价>）【<YYYY-MM-DD>建仓·<时段：盘前/竞价/盘中/收盘>·<逻辑摘要>】
```

**示例（合规）：**
```
- 长江通信 600345（200股，成本56.83）【2026-06-05建仓·盘中买入·通信设备/光纤方向】
```

**字段定义：**
| 字段 | 必填 | 来源 | 校验 |
|---|---|---|---|
| 名称 | ✅ | 券商截图 | 与代码一致 |
| 代码 | ✅ | 券商截图 | 6 位数字 |
| 数量 | ✅ | 券商截图 | 100 的倍数 |
| 成本价 | ✅ | 券商截图（含手续费） | 保留 2-3 位小数 |
| 建仓日期 | ✅ | 当日 | YYYY-MM-DD |
| 时段 | ✅ | 辉哥告知 | 盘前/竞价/盘中/收盘 |
| 逻辑摘要 | ✅ | 辉哥告知或对话上下文 | 一句话，不超 30 字 |

### F2 · 止损/止盈登记字段（建议附加）
建议在备注后追加：

```
·止损<价>·目标<价>
```

**示例：**
```
- 北京君正 300223（100股，成本147.89）【2026-06-04建仓·盘中介入·止损135.0·目标165.0】
```

未指定时默认使用 **风控规则 R2**（成本×0.95），后续报告必须显式说明"沿用默认 -5% 止损"。

### F3 · 清仓登记字段
清仓后**不删除原条目**，在末尾追加清仓信息：

```
- <名称> <代码>（<原数量>股，成本<原成本>）【...建仓信息...】【<YYYY-MM-DD>清仓@<清仓价>·盈/亏<金额>(±X%)·<原因>】
```

**示例（合规）：**
```
- 卧龙电驱 600580（200股，成本44.455）【2026-06-04清仓@38.15·止损执行·浮亏约¥-1,261(-12.7%)】
```

同时在 TOOLS.md 末尾 "今日清仓记录" 节追加同步条目（用于周/月复盘聚合）。

### F4 · 部分减仓登记字段
减仓后**修改原条目数量**，并追加减仓事件：

```
- <名称> <代码>（剩余<数量>股，成本<成本>）【...原建仓信息...】【<YYYY-MM-DD>减仓<数量>@<价>·<原因>·剩余止损调整至<新止损价>】
```

## 三、变更操作 SOP（标准操作流程）

### SOP-1 · 建仓登记
```
1. 辉哥告知建仓 →
2. AI 提取字段（名称/代码/数量/成本/时段/逻辑）→
3. AI 核对 TOOLS.md 当前不含该标的（避免重复登记）→
4. AI 按 F1 格式追加到 TOOLS.md 持仓节 →
5. AI 同步更新 focus_watchlist.json：
   - 该标的存在 → hold=true, status="持仓", 更新 entry/止损/止盈/note
   - 该标的不存在 → 新增条目 hold=true
6. AI 回复辉哥确认："✅ 已登记 <标的> 持仓，止损默认 X.XX（成本×0.95），止盈区间需要您指定吗？"
```

### SOP-2 · 清仓登记
```
1. 辉哥告知清仓（含清仓价）→
2. AI 提取字段（清仓价/数量/原因）→
3. AI 计算盈亏 = (清仓价 - 成本价) × 数量 - 手续费估算
4. AI 按 F3 格式修改 TOOLS.md 持仓条目 →
5. AI 在 TOOLS.md "今日清仓记录" 节追加同步条目 →
6. AI 同步 focus_watchlist.json：
   - hold=false, status="已清仓"
   - note 字段追加清仓信息和盈亏
7. AI 回复辉哥确认："✅ 已登记 <标的> 清仓，盈/亏 ¥X (±X%)，本周累计盈亏 ¥X"
8. AI 检查是否需要触发风控规则 R4（同标的复仓冷却）
```

### SOP-3 · 加仓/减仓登记
```
1. 辉哥告知加/减仓（数量/价格）→
2. AI 重新计算加权平均成本（加仓）或保留原成本（减仓）→
3. AI 按 F4 格式修改 TOOLS.md →
4. AI 校验风控规则 R3（单票 20% 上限）和 R7（总仓位上限）→
5. AI 同步 focus_watchlist.json note 字段
```

### SOP-4 · 调整止损/止盈
```
1. 辉哥告知新止损/止盈 价 →
2. AI 校验是否符合风控规则 R10（移动止损规则）：
   - 浮盈 >+10% 不得低于保本止损（成本价）
   - 浮盈 >+20% 不得低于成本价×1.10
3. AI 更新 TOOLS.md 持仓条目备注和 focus_watchlist.json
4. AI 回复确认新止损/止盈价
```

## 四、数据一致性校验（强制）

### V1 · 写入前校验
任何持仓变更写入 **TOOLS.md 之前**，AI 必须完成：

```
✅ 标的代码 6 位数字校验
✅ 数量为 100 倍数校验
✅ 成本价数值合法（>0，≤ 当日涨停价）
✅ 与现有持仓不冲突（建仓时无重复，清仓时存在该标的）
✅ 当日 T+1 约束校验（清仓标的的建仓日 < 今日）
```

任一项不通过：**停止写入，向辉哥追问**，不得自行猜测。

### V2 · 写入后三件同步
变更写入 TOOLS.md 后，**同一个对话回合内必须完成**：

1. ✅ TOOLS.md 持仓节已更新
2. ✅ focus_watchlist.json hold/status/note 已同步
3. ✅ （如需精确）触发 `python3 scripts/daily_settlement.py` 刷新 settlement.json

如第 2、3 步漏做，下次盘前作战会出现"focus 显示 hold=true 但 TOOLS.md 已清仓"的不一致，必修。

### V3 · 每日开盘前一致性扫描
盘前作战 cron（08:30）必须在第 -1 步执行一致性校验（已在 prompt 中实现），发现不一致先修复再继续：

```
exec grep -A 50 '^### 持仓' TOOLS.md  → 提取真实持仓列表
exec cat stock-signals/focus_watchlist.json  → 对比 hold=true 标的
不一致 → 修复 focus_watchlist → 再生成报告
```

## 五、违规防护（基于历史教训）

### 历史事件参考

| 日期 | 事件 | 原因 | 本规则对应防护 |
|---|---|---|---|
| 06-01 | 长盈精密"误清仓" | 脚本信号 → AI 推断清仓 → 未与券商截图校对 | S1 唯一信任源、V2 写入后同步 |
| 06-02 | 蓝色光标连环复仓 | 同标的 3 日内复仓未做消除判断 | SOP-2 第 8 步触发 R4 校验 |
| 多次 | focus_watchlist 与 TOOLS.md hold 状态不一致 | 清仓后未同步 focus | V2 三件同步、V3 每日开盘前扫描 |

### 防护原则
- **宁可追问，不可猜测**：所有不明字段一律追问辉哥
- **宁可漏报，不可错报**：数据一致性失败时拒绝生成报告，不得带病推送

## 六、规则维护

- 修订后必须同步更新所有引用本文件的 cron prompt
- **禁止 AI 自主修改本文件**

# 数据流水线规则 v1.0

**生效日期：** 2026-06-06
**适用范围：** 所有数据生产类 cron 和脚本（pipeline.sh / engine.sh / layer_monitor.py / signals_summary.py / price_cache.sh / portfolio_engine.py / daily_settlement.py）
**核心定位：** 数据生产层（无推送、无分析、只产文件）

> **核心契约：** 任何报告类 cron 启动时，必须能在 `/tmp/stock_alerts/` 找到约定文件。本规则定义"什么时间产什么文件、由谁产、依赖什么、新鲜度阈值、失败如何降级"。

## 三、依赖关系图

```
gtimg API
  ↓

engine_signals.json (189KB全量信号)
  ├─→ layer_monitor.py → L1-L6.txt + urgent.txt

  └─→ sector_fund_flow.py → sector_flow.json
                              ↓
                           industry_chain.py → chain_alerts.json

TOOLS.md (持仓)
  ↓
portfolio_engine.py → data/portfolio_snapshot.json
  ↓

```

**严格约束：** 下游脚本必须检查上游文件存在性，缺失时 **使用上次缓存或显式报错**，不得静默产出空数据。

## 四、互斥与锁

### M1 · 文件锁
`pipeline.sh` 使用 `/tmp/pipeline.lock` flock 互斥，**禁止两个 pipeline 同时跑**。
监控密集时段（9:33-15:00 每15分钟）+ 收盘多个 cron 排队，锁机制保证不会数据撕裂。

### M2 · 数据原子性
所有 `.json` 文件写入必须先写 `.tmp` 再 `mv` 重命名（避免读到半写文件）。
**目前 layer_monitor.py / signals_summary.py 仍是直接 open(w)，需要后续整改**（列入技术债）。

## 五、新鲜度校验规则

### F1 · 报告 cron 启动前必须自检数据新鲜度
所有报告类 cron 在读 `/tmp/stock_alerts/*` 前必须执行：

```bash
# 检查关键文件 mtime 距当前是否 < 15min
for f in L1_market.txt L2_holdings.txt signals_summary.json; do
    AGE=$(($(date +%s) - $(stat -c %Y /tmp/stock_alerts/$f 2>/dev/null || echo 0)))
    if [ "$AGE" -gt 900 ]; then
        echo "⚠️ $f 数据陈旧 ${AGE}s"
    fi
done
```

报告中必须标注数据时间戳（如"数据时点 14:33"），避免读旧数据而不自知。

### F2 · 持仓数据强一致性
`L2_holdings.txt` 必须与 TOOLS.md 持仓节一一对应：
- TOOLS.md 有但 L2 没有 → 漏采，需调用 `layer_monitor.py` 重跑
- L2 有但 TOOLS.md 没有 → 已清仓未清理，需修复

由盘前作战 cron 第 -1 步触发（已在《重点关注清单维护规则》SOP-M3 中规定）。

## 六、失败处理规则

### E1 · 单脚本失败
- `engine.sh` 失败 → 使用 `engine_signals.json` 上次缓存（最长 30min）
- `layer_monitor.py` 失败 → 使用 L1-L6 上次缓存
- `sector_fund_flow.py` / `industry_chain.py` 失败 → 报告中"板块资金/产业链"段标注"数据不可用"
- `portfolio_engine.py` 失败 → 盘后审计退化为"仅持仓行情，无净值变化"

### E2 · pipeline cron 整体失败
- `consecutiveErrors >= 2` → cron 自动告警推送到辉哥微信（已配置 failureAlert）
- 失败原因 timeout 优先级最高（已发生过多次）：需排查 model-call 阶段

### E3 · 数据源 API 失败（gtimg/curl 超时）
- 单次重试 1 次（已在 engine.sh / layer_monitor.py 中实现）
- 二次失败 → 跳过该轮，下次轮询补齐

## 七、运维规则

### O1 · 禁止人工写入 /tmp/stock_alerts/
辉哥/AI 任何手动操作禁止往 `/tmp/stock_alerts/` 写文件——只有 pipeline.sh 链路可写。
人工调试用 `cp` 到 `/tmp/test_alerts/` 目录另作分析。

### O2 · cron 调度密度上限
- 单一 cron schedule 表达式不得 < 5min 间隔
- pipeline 类总并发不得 > 2（M1 锁兜底）

### O3 · 日志保留
- `/tmp/pipeline.lock` 不需要持久化
- 失败日志保留在 cron `lastDiagnostics` 字段，AI 可定期查询体检

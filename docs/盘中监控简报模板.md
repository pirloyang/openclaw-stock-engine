# 盘中监控简报模板 v2.0

**生效日期：** 2026-06-13
**适用 cron：** 盘中监控-早盘（09:35/50）、盘中监控-早盘B（10:05/20/35/50 + 11:05/20）、盘中监控-午盘（13:05/20/35/50 + 14:05/20/35/50）
**触发频率：** 整个交易日约 18 条简报（含开盘 1 条 + 早盘 4 条 + 早盘B 6 条 + 午盘 8 条；午休 11:30-13:00 不发）

> **核心定位：** 盘中简报是辉哥盯盘期间的"贴身警卫"，必须做到**短、准、有判断**。不堆数据，只给可执行结论。

---

## 一、输出格式（强制）

### 总字数上限
**2000 字以内**（微信单条消息上限保护）

### 六段固定结构（不可改）

```
1️⃣ 大盘 · <一句话气质判断>

2️⃣ 持仓 · <每只一句：现价/涨跌/状态/操作>
- <名称>(代码) ¥X.XX <±X.X%> · <核心判断> · <操作建议（必含规则索引）>
...

3️⃣ 重点监控 · <持仓+直接触发标的，≤5只>
- <名称>(代码) ¥X.XX <±X.X%> · <信号摘要> · <介入/观望>
...

4️⃣ ETF/概念 · <异动板块一句话>

5️⃣ 自选+热点 · <涨跌停/±8%极端信号汇总>

6️⃣ 紧急信号 · <持仓相关 urgent 信号；无则"无"; 不夹带非持仓>

【风控·v1.0】R1 T+1:OK · R2 止损:N只 · R11 看空持仓:N只 · R13 白名单:OK
```

## 二、内容规则

### C0 · 监控执行总则（强制）

盘中监控分两类场景，规则不同：

**① 持仓标的（存量头寸）— 按盘前指令执行，不创造新判断**
- 必须读取当日盘前作战报告（`reports/YYYY-MM-DD-0830-盘前作战.md`）中对应标的的「关键价位」和「场景推演」
- 将实时价格与关键价位对比 → 落入哪个场景 → 执行该场景对应的动作
- 输出格式：`[盘前场景] · [实时价vs关键价位] · [执行动作]`
- **禁止：** 对持仓标的在盘中自行发明新的支撑位/压力位/买卖条件。所有价位锚点必须来自盘前指令。

**② 新机会标的（盘中扫描发现）— 必须结合大盘行情发现并制定新策略**
- 盘中监控必须持续扫描全池，结合大盘气质、板块异动、个股量价形态发现新机会
- 对新机会标的，盘中监控**必须**制定完整的操作策略：
  - 关键价位（当前阻力/支撑）
  - 介入条件（什么价位、什么量能条件可以进）
  - 止损位
  - 预期空间
- 输出格式：`🆕 [标的] · [催化逻辑] · [操作策略：介入价/止损/目标]`
- **新机会策略将在12:00午间修正或15:30盘后审计中与盘前指令合并，纳入次日盘前作战**

### C1 · 大盘段（≤30字）
- 涨跌 + 量能 + 主线
- 示例：`"科创50领涨1.8%，万亿成交，AI算力主线再启"`
- 禁止：堆指数点位、复述涨跌幅细节

### C2 · 持仓段（每只≤60字）
- 必含字段：名称、代码、现价、涨跌幅、核心判断、操作建议
- 操作建议必须含规则索引（R1/R2/R10/R11 等）
- **操作建议必须引用盘前指令中的场景推演**，格式：`[盘前场景名] · [当前价位vs关键价位] · [执行动作]`
- 示例：
  - `中国铝业(601600) ¥11.42 +0.7% · 站稳MA5，独立走强 · 持有不动`
  - `紫光国微(002049) ¥77.50 -5.3% · 跌破止损82.65 · 按R2 建议清仓`
  - `信维通信(300136) ¥107.20 -0.5% · 当日建仓T+1锁定 · R1 仅持仓不议卖`

### C3 · 重点监控段
- 上限 5 只
- 优先级：持仓 > 盘前作战新机会标的（今日竞价/开盘表现跟踪） > focus_watchlist 中 hold=false 但 status="重点监控" > 当日 urgent.md 触发标的
- 盘前作战新机会标的：从当日盘前作战报告「新机会关注」节读取，跟踪其竞价/开盘/盘中表现，**严格按盘前指令中的关键价位和场景推演执行**，给出「✅介入 / ⏳等待回踩 / ❌放弃」判断
- 已清仓标的（hold=false + status="已清仓"）**不出现**

### C4 · ETF/概念段（≤80字）
- 只写涨幅 > 2% 或跌幅 > 2% 的板块
- 配对：`<板块名> +X.X% / -X.X% · <主导逻辑>`

### C5 · 自选+热点段（≤200字）
- **只写极端信号**：涨停 / 跌停 / 涨幅 ≥ 8% / 跌幅 ≥ 8%
- 数据源：L5_watchlist.txt + L6_hot_alerts.txt
- 格式：`<名称>(代码) ±X.X% · <原因/板块>`

### C6 · 紧急信号段（≤150字）
- 只留 **持仓相关** urgent 信号
- 已清仓标的不出现
- 无紧急信号 → 写"无"，不要省略本段

## 三、风控规则强制接入

### V1 · 持仓建议必须先校验风控规则
对每只持仓的操作建议，必须按以下顺序校验：

| 校验项 | 数据源 | 违规时的输出 |
|---|---|---|
| R1 T+1 | 建仓日期 = 今日 | 卖出建议改为"T+1锁定，明日再评估" |
| R2 -5%止损 | 现价 ≤ 成本×0.95 或跌破技术止损位 | 必须出现"按R2 建议执行止损" |
| R10 移动止损 | 浮盈 > 10%，止损位是否已上移 | 必须出现"R10 止损上移至成本/<新位>" |
| R11 信号一票否决 | signals_summary.json 形态信号看空 | 禁止加仓建议 |

### V2 · 一行风控自检（必输出）
报告末尾必须输出一行（占字数约 60 字）：

```
【风控·v1.0】R1 T+1:OK · R2 止损:N只 · R11 看空持仓:N只 · R13 白名单:OK
```

字段含义：
- `R1 T+1:OK` = 已正确识别当日建仓标的并锁定卖出建议
- `R2 止损:N只` = 当前触止损线的标的数量
- `R11 看空持仓:N只` = 信号引擎看空的持仓数量（必须未给加仓建议）
- `R13 白名单:OK` = 已清仓标的零出现

## 四、数据源使用规则

### D1 · 数据来源严格分层
| 数据源 | 用途 | 禁止用途 |
|---|---|---|
| L1_market.md | 大盘段 | 持仓段 |
| L2_holdings.md | 持仓段实时行情 | 持仓字段（成本/数量来自 TOOLS.md）|
| L3_focus.md | 重点监控段 | 自选段 |
| L4_etf_concept.md | ETF/概念段 | 持仓段 |
| L5_watchlist.md | 自选段 | 已清仓标的 |
| 盘前作战报告「新机会关注」节 | C3重点监控段（盘前作战新机会跟踪） | 持仓段 |
| L6_hot_alerts.md | 自选+热点段 | 重点监控段 |
| urgent.md | 紧急信号段（仅持仓相关） | 持仓段操作建议 |
| signals_summary.json | 所有段的信号交叉验证 | 价格/涨跌幅 |
| TOOLS.md | 持仓清单+成本+建仓日期 | 实时价格 |

### D2 · 数据新鲜度校验
**所有价格/涨跌幅数据必须从gtimg实时API拉取，缓存文件只用于信号形态参考。**

实时拉取后执行对比校验：
- 实时价格 vs 缓存价格偏差 < 1% → 正常
- 偏差 1-5% → 报告标注"⚠️ 数据偏差"
- 偏差 > 5% → 报告首段提示"⚠️ 数据陈旧，已用实时数据覆盖"

缓存文件mtime检查（辅助）：
- 距今 < 5min → 正常
- 距今 5-15min → 报告标注"数据时点 HH:MM"
- 距今 > 15min → 仅作信号参考，价格以实时为准

## 五、违规防护

### 历史问题与对应规则
| 问题 | 对应规则 |
|---|---|
| 简报里出现已清仓标的 | C3/C6 已清仓白名单 + V2 R13 |
| 持仓段无操作建议或建议不带规则索引 | C2 操作建议必含规则索引 |
| 简报超字数被微信截断 | 总字数上限 2000 + 各段字数上限 |
| 重点监控段写太多（>10 只）冲淡持仓 | C3 上限 5 只 |
| 当日建仓被简报建议卖出（违 T+1）| V1 R1 校验 |

## 六、模板使用规则

### U1 · cron prompt 必须引用本模板
盘中监控类 cron（3 个）的 prompt 中必须包含：
```
【前置·模板加载】exec cat /root/.openclaw/workspace/docs/盘中监控简报模板.md
严格按本模板的六段结构、字数上限、风控接入规则生成简报。
```

### U2 · 修订流程
- 修订需辉哥确认 → AI 草拟 → 写入 +版本号
- 修订后必须同步更新 3 个盘中监控 cron 的 prompt
- **禁止 AI 自主修改本文件**

# 重点关注清单维护规则 v1.0

**生效日期：** 2026-06-06
**适用范围：** `stock-signals/focus_watchlist.json` 文件的所有读写操作
**配套规则：** `交易风控规则.md`、`持仓变更登记规则.md`

> **核心定位：** `focus_watchlist.json` 是辉哥精选的「重点关注清单」，**不是持仓清单**。它服务于盘前/盘中/盘后报告的强制覆盖，是 AI 在所有股票相关报告中必须优先扫描的标的池。

---

## 一、清单的定位与边界

### D1 · 三类标的池的边界
| 池子 | 来源 | 用途 | 权威源 |
|---|---|---|---|
| **持仓池** | 辉哥告知 | 真实交易决策 | TOOLS.md 持仓节 |
| **重点关注清单** | 辉哥指定加入 | 报告强制覆盖 + 信号引擎重点扫描 | `focus_watchlist.json` |
| **自选监控池** | TOOLS.md "自选监控（盘中扫描）" 节 + 历史持仓 | 全量扫描 | TOOLS.md |

**关键边界：**
- 持仓 ⊂ 重点关注（持仓必然在重点关注中，反之不一定）
- 重点关注 ⊂ 自选监控（重点关注是自选的精选子集）
- 清仓 ≠ 移出重点关注（清仓后可保留在重点关注做二次介入观察）

### D2 · hold 字段语义（严格定义）
| hold 值 | status 值 | 含义 |
|---|---|---|
| `true` | `"持仓"` | 当前持有，TOOLS.md 持仓节有该条目 |
| `false` | `"已清仓"` | 历史持有过、当前未持有，等待二次介入信号 |
| `false` | `"重点监控"` | 未持有过、辉哥指定监控，等待首次介入信号 |
| `false` | `"观察"` | 候选标的，未满足介入条件 |

**严格约束：** `hold=true` ↔ TOOLS.md 持仓节包含该标的，**双向一一对应**。

## 二、清单字段标准

### F1 · 必填字段
每条记录必须包含：

```json
{
  "code": "600345",          // 6位代码
  "name": "长江通信",          // 中文名
  "stars": 3,                // 1-5 星，重要性
  "hold": true,              // 严格遵循 D2 语义
  "status": "持仓",            // 严格遵循 D2 语义
  "catalyst": "...",         // 催化逻辑一句话
  "entry_low": 56.0,         // 介入区间下限
  "entry_high": 57.5,        // 介入区间上限
  "stop_loss": 54.0,         // 止损价
  "target": 62.0,            // 目标价
  "signals": ["..."],        // 关键介入/卖出信号
  "note": "..."              // 备注（含持仓数量/成本/二次介入条件等）
}
```

### F2 · 字段合规性校验
| 字段 | 校验规则 |
|---|---|
| `code` | 6 位数字，全清单内唯一 |
| `name` | 与代码对应，与 TOOLS.md 一致 |
| `stars` | 1-5 整数 |
| `hold` / `status` | 必须符合 D2 配对表 |
| `entry_low` / `entry_high` | low ≤ high，均 > 0 |
| `stop_loss` | < entry_low，且 < 现价（若 hold=true） |
| `target` | > entry_high |

## 三、加入清单的触发条件

### A1 · 主动加入（辉哥指定）
- 辉哥说"加入重点关注 XXX" / "重点监控 XXX" → 立刻新增条目
- AI 必须追问缺失字段：催化逻辑、介入区间、止损、目标价

### A2 · 自动加入（建仓即加）
- 任何持仓变更登记规则 SOP-1 完成后，**该标的必须存在于重点关注清单**（hold=true）
- 若不存在 → AI 主动新增条目，使用建仓信息回填字段，并向辉哥确认 stars 等级

### A3 · 不允许自动加入的情况
- 信号引擎扫描出涨幅榜标的 → **禁止**自动加入，需辉哥审核
- 信息炼金/周末风口研报中的"候选标的" → 写入 `fengkou_candidates.json`，不直接进重点关注

---

## 四、移除清单的触发条件

### R1 · 主动移除（辉哥指定）
- 辉哥说"移出 XXX" / "不关注了 XXX" → 删除条目
- 删除前 AI 必须二次确认（避免误删）

### R2 · 自动降级（不删除）
持仓清仓时**不删除**，按以下顺序处理：
1. SOP-2 触发 → 修改 hold=false, status="已清仓"
2. note 字段追加清仓信息和盈亏
3. 标的保留在清单中，作为"二次介入候选"
4. 30 天后未再次触发任何信号 → AI 可建议辉哥审核是否移除（不自动删）

### R3 · 静默标的清理
- 连续 60 天无价格异动、无新闻催化、无技术信号 → AI 在月度复盘中提示"建议移除"，等辉哥确认

## 五、清单覆盖使用规则

### U1 · 强制覆盖场景
以下 cron 报告必须**完整覆盖**清单中**所有**标的（不得遗漏）：

| Cron | 覆盖要求 |
|---|---|
| 盘前作战指令（08:30）| 第二段必须逐只覆盖 hold=true 标的 + status="重点监控" 标的 |
| 午间修正（12:00）| 持仓段必须逐只覆盖 hold=true 标的 |
| 盘后审计（15:30）| 持仓段必须逐只覆盖 hold=true 标的 |
| 结构重塑（21:00）| 必须分组覆盖：持仓 / 重点监控 / 观察 |
| 信息炼金（22:00）| 第四节交叉验证必须覆盖 hold=true + status="重点监控" 标的 |

### U2 · 分层数据流水线
`L3_focus.txt` 必须从 `focus_watchlist.json` + 静态自选池读取：
- `focus_watchlist.json` 中所有标的 → L3_focus.txt（高优先级）
- TOOLS.md "自选监控（盘中扫描）"节 → 补充（低优先级）

## 六、维护操作 SOP

### SOP-M1 · 新增标的
```
1. 辉哥指定 / 建仓触发
2. AI 收集所有 F1 必填字段（缺则追问）
3. AI 校验 F2 合规性
4. AI 写入 focus_watchlist.json，更新 last_update 字段
5. AI 回复确认："✅ <标的> 已加入重点关注，star=N，entry [X-Y]，止损 Z"
```

### SOP-M2 · 状态变更（建仓/清仓/调止损）
```
1. 触发自《持仓变更登记规则》SOP-1/2/3/4
2. AI 修改 focus_watchlist.json 对应条目：hold/status/note/stop_loss/...
3. 更新 last_update 字段
4. 不删除条目（除非辉哥明确要求移除）
```

### SOP-M3 · 清单一致性自检
每日盘前作战（08:30）第 -1 步执行：
```python
# 伪代码
hold_in_focus = [f["code"] for f in focus if f["hold"]]
hold_in_tools = parse_positions_from_tools_md()
if set(hold_in_focus) != set(hold_in_tools):
    fix_focus_watchlist()  # 以 TOOLS.md 为准
    log("⚠️ 已修复 focus_watchlist 与 TOOLS.md 不一致")
```

历史教训：05-31 之前多次出现"clearance 后 focus 未同步"，必须每日开盘前修。

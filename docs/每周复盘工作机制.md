# 每周复盘工作机制 v1.0

**生效日期：** 2026-06-06
**适用 cron：** 每周复盘（周五 16:00）
**配套文件：** `docs/每周复盘模板.md`

> **核心定位：** 每周五收盘后对一周交易、组合健康度、策略表现做系统化复盘，是连接日报告与月报告的桥梁。

---

## 一、运行机制

### 时间窗口
- **每周五 16:00**（节假日顺延到最近一个交易日收盘后）
- 超时 600s

### 上游输入
| 数据源 | 用途 |
|---|---|
| `TOOLS.md` "今日清仓记录" 节 | 本周所有清仓事件 |
| `TOOLS.md` 持仓节 | 周末持仓清单 |
| `data/portfolio_snapshot.json` 周一/周五 | 周净值变化 |
| `data/settlement.json` | 当日结算数据 |
| 本周 5 日的 `reports/YYYY-MM-DD-1530-盘后审计.md` | 日复盘聚合 |
| `data/goals.json`（若有）| 里程碑进度 |

### 执行步骤
```
1. 加载规则文件（《风控规则》《持仓变更登记规则》）
2. 加载模板 docs/每周复盘模板.md
3. 运行 python3 scripts/monitor_full.py 获取最新行情
4. 读取本周 TOOLS.md 持仓变化 + 5 份盘后审计报告
5. 按模板七节生成（操作回顾/账户变化/组合健康度/策略评分/风险看板/下周策略/进度跟踪）
6. write 到 reports/weekly/YYYY-WW-周复盘.md
7. 推送给辉哥
```

### 下游消费
- **月度绩效审计** 聚合 4-5 份周复盘
- **辉哥本人** 周末决策参考

## 二、内容规则

### C1 · 本周操作回顾
- 数据源：TOOLS.md "今日清仓记录" 节 + 持仓节
- 必须列：每笔清仓的 标的/数量/成本/清仓价/盈亏金额/盈亏%/原因
- 加仓/减仓/建仓事件同样列出
- **不得遗漏**，按时间倒序

### C2 · 账户变化
- 期初净值（周一开盘前）→ 期末净值（周五收盘后）
- 周内最大回撤、最大盈利
- 已结盈亏 vs 浮动盈亏分开列

### C3 · 组合健康度（4 项打分）
- **仓位健康**：当前总仓位 vs 60-80% 目标区间
- **集中度健康**：最大单票占比 vs 20% 上限（《风控规则》R3）
- **风险敞口**：触止损线/已减仓/正常 各几只
- **方向多元化**：科技/资源/金融/消费 仓位分布

### C4 · 本周策略评分
- 本周盘前作战预判命中率（取 5 份报告的核心判断 vs 实际走势）
- 信号引擎共振判定命中率
- 风控规则执行情况（是否有违规、是否所有止损按 R2 执行）

### C5 · 风险看板更新
- 当前持仓中浮亏 > -3% 的标的
- 已达 R10 移动止损触发条件但未上移的标的
- 持仓与 focus_watchlist 一致性状态

### C6 · 下周策略调整
- 建议：减仓/加仓/换仓的具体标的与价位
- 必须符合《风控规则》R1/R2/R3/R10/R11
- 给出明确的下周观察清单（≤ 5 只）

### C7 · 进度跟踪
- 当前账户净值距离 20-30 万目标的百分比
- 周环比、月环比、累计盈亏

## 三、自律规则

| 规则 | 说明 |
|---|---|
| R1 | 操作以 TOOLS.md 清仓记录为唯一权威，不得凭记忆 |
| R2 | 净值数据从 portfolio_snapshot.json 读，不得自己估算 |
| R3 | 已清仓标的的"教训"部分必须包含原因+对策 |
| R4 | 下周策略建议必须符合《交易风控规则》R1/R2/R3/R10/R11 |
| R5 | 报告 write 到 reports/weekly/YYYY-WW-周复盘.md |
| R6 | 末尾必输出风控自检（《风控规则》R16）|

---

## 四、失败处理

| 失败模式 | 处理 |
|---|---|
| portfolio_snapshot.json 缺失 | 报告标注"⚠️ 净值数据不可用"，跳过 C2/C7 |
| 本周报告残缺（< 5 份）| 报告标注"⚠️ 本周仅 N 个交易日数据" |
| monitor_full.py 失败 | 使用 settlement.json 最新数据降级 |
| cron timeout | failureAlert → 辉哥微信告警 |

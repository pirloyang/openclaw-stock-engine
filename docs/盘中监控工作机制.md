# 盘中监控工作机制

> 关联总纲：`docs/全链路报告闭环体系.md`

---

## 一、定位

**盘中监控是双角色：持仓执行器 + 新机会发现器。**

- **持仓标的：** 盘前指令的执行器。把盘前作战指令中每个持仓标的的「关键价位」和「场景推演」与实时行情对比 → 落入哪个场景 → 执行该场景对应的动作。不创造新判断，不发明新价位。
- **新机会标的：** 盘中扫描发现器。必须结合大盘气质、板块异动、个股量价形态持续扫描全池，发现新机会并制定完整操作策略（关键价位+介入条件+止损+目标）。

盘中监控是全天实时行情扫描系统。**不是报告，是信号系统。** 每10分钟扫描全池，有介入信号才推，全池安静则NO_REPLY。

与盘后报告严格分离：盘中监控只做实时信号推送，不做复盘分析。

---

## 二、调度

- **时段**：09:35 ~ 14:55 每10分钟一次（交易日）
- **执行**：27个cron任务（09:35~11:55 + 13:05~14:55）
- **脚本**：`bash /root/.openclaw/workspace/scripts/smart_monitor.sh`
- **超时**：300秒（已扩容）
- **推送**：delivery → openclaw-weixin（已修复）

---

## 三、监控范围

监控脚本自动扫描 `tools.sh` 中定义的全部标的，包括：
- 持仓标的（8只）
- ETF自选（5只）
- 概念指数（4个）
- 历史自选池（45只）
- 核心自选（辉哥君弘截图）
- 新增风口监控（航空/化工/设备/存储，每日22:00更新）
- 商业航天（12只）

---

## 四、推送触发条件

**必须同时满足以下条件才推送：**
1. 板块集体异动涨超2%
2. 个股量能配合（放量突破5日线或跌破支撑位）
3. 有明确的买卖判断（不是单纯涨跌通报）

**推送内容三要素：**
1. 判断依据（简洁但足以看懂和信服）
2. 具体买卖价格与数量
3. 清仓/减仓/加仓的明确操作指令

**推送附加四要素（解盘）：**
1. 位置判断（所处趋势位置）
2. 定性分析（上涨/下跌性质判断）
3. 交易条件与情景（触发买卖的条件描述）
4. 止损价（明确的止损价位）

**不推送的场景：**
- 单一个股涨跌无板块共振 → 不推
- 价格波动无量能配合 → 不推
- 异动发生在14:30之后 → 盘后总结说，盘中不推
- 全池安静 → NO_REPLY

---

## 五、数据纪律

- 脚本输出的止损/买入/卖出信号是**系统建议**，不是用户交易记录
- 推送时只说"XX触发XX条件"，不说"你卖了XX/你买了XX"
- 只有TOOLS.md持仓段明确的标的才是用户持仓，其他按监控池对待
- 优先关注大盘指数（上证/深证/创业板/科创50）再分析个股
- 先判断市场整体环境（三色分级），再分析个股操作

---

## 六、前置引用（强制）

### 6.1 持仓标的：必须读取当日盘前作战指令

盘中监控推送**必须**先读取当日盘前作战报告：
```
exec cat reports/$(date +%Y-%m-%d)-0830-盘前作战.md
```

读取后，每只持仓标的的操作建议必须引用盘前指令中的场景推演：
> "[标的]盘前指令：高开>XX减仓 / 开在XX-XX持有 / 低开破XX清仓。当前价XX，落入[场景名]——执行[对应动作]"

### 6.2 新机会标的：盘中扫描发现 + 制定新策略

盘中监控必须持续扫描全池，结合大盘气质和板块异动发现新机会。对新机会标的：
1. 制定完整操作策略（关键价位+介入条件+止损+目标）
2. 在推送中输出策略
3. 标注：`🆕 新机会策略，将纳入12:00午间修正/15:30盘后审计评估，合并入次日盘前作战`

### 6.3 结尾指向

**结尾必须指向12:00午间修正或15:30盘后审计：**
> "上述信号已记录，将纳入12:00午间修正的策略评估"
